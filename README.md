# Process-engine blueprints

[![CI](../../actions/workflows/ci.yml/badge.svg)](../../actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

Ready-to-start blueprints for automating a business process with a process engine. Every example
automates the same fictional **MiraVelo bike-leasing** process, so they differ only in what you came to
compare: the **engine** (CIB seven, Operaton, Fluxnova, Camunda 8), **how the service talks to it**
(embedded JavaDelegates, external tasks against a remote engine host, the bpm-crafters
process-engine-api, Zeebe job workers, VanillaBP) and the **language** (Kotlin + Gradle or Java + Maven).

Each folder under [`examples/`](examples/) is a complete, self-contained project: its own build, its own
dependencies, its own local stack, API scenarios, ADRs and agent tooling. Nothing is shared at build or run
time. The duplication is deliberate, so that one example can become your project without the others.

**Topology** is the stack option: `embedded` runs the engine inside your Spring Boot service, next to
Postgres; `remote` runs it as its own process (a generic engine host, or a Camunda 8 cluster) that your
service works against.

## Start your own project

One command gives you one example in one language as a flat project with a fresh git history, the
package and the project renamed:

```bash
npm create miragon-blueprint@latest my-service
# or without questions
npm create miragon-blueprint@latest my-service -- --example cibseven-embedded --lang kotlin --package com.acme.leasing
```

Every release of an example also attaches the starters as plain archives
(`<example>-kotlin-gradle.tar.gz`, `<example>-java-maven.tar.gz`) if you'd rather not run the CLI. From a
checkout of this repository, `tooling/starter/export.sh <example> <kotlin-gradle|java-maven> <dir>` builds
the same starter locally. See [`tooling/create-blueprint`](tooling/create-blueprint/README.md).

## Work on an example

Open the example's folder, not the repository root: every example's README, `AGENTS.md`, `.claude/`
skills and Conductor targets assume that folder is the project.

```bash
cd examples/cibseven-embedded
npm ci                                            # BPMN tooling of this example
docker compose -f stack/docker-compose.yml up -d  # its local stack
```

## Links that stay

Training material and talks link to `examples/<example>/README.md` and to anchors in it. Example folders
are never renamed or removed without leaving a README at the old path that points to the new one.
